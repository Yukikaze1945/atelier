# 时间线真实时长与播放修复

## 原因与改动

- 前端元数据探测跳过 MKV，Core 在没有时长时为视频填入五秒。导入和旧素材插入现在使用原生 GStreamer Discoverer 补齐缺失时长；失败保留可诊断错误，不再伪造视频/音频时长。静态图片仍默认五秒。
- 拖入/添加片段后选中新增片段并将播放头移到片段起点，避免监看器仍停留在空白区域。
- 时间线监看器不再逐帧写入 `currentTime` 和重复调用 `play()`。以实际媒体播放时间驱动播放头，仅在用户跳转或源加载时定位；媒体未就绪时不让时间线空跑。加载/播放失败显示错误。
- 真实长 MKV 暴露了本地媒体协议的随机访问问题：播放器报告可跳转区间 `[0, 0]`。协议现在显式实现 `Accept-Ranges`、206、`Content-Range`、HEAD 和 416，并按需流式读取字节，不把完整视频装入内存。
- 已存在的五秒片段不自动拉长，避免破坏有意裁剪。选中视频/音频片段，在检查器点击“恢复完整源时长”可恢复零入点和真实源时长，保留位置和轨道，一次撤销可还原。

## 回归方法

`tests/e2e/timeline-playback.spec.ts` 默认生成九秒 MKV，通过真实 Electron 界面导入、拖拽，检查 Core 保存的时长、媒体解码帧计数、播放时间前进、暂停、跳转完成及完整源时长恢复/撤销。

设置 `WORKSTATION_TEST_MEDIA` 可在独立临时工程中只读引用外部视频。用户的 117.888 秒、3840×2160、120 fps MKV 已用于真实回归，原工程未修改。

另有 Core 回归覆盖音视频未知时长拒绝五秒回退、静态图片默认时长、完整源时长恢复及撤销；媒体协议单测覆盖完整读取、HEAD、固定区间、后缀、开放区间和非法范围。

## 边界

此次修复的是现有 HTML 媒体时间线监看路径，不代表完整 GES 多轨实时合成或端到端 GPU 零拷贝已接通，也不保证 Chromium 不支持的所有编解码格式均可预览。
