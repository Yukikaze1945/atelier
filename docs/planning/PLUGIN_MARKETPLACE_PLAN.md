# AI 创作工作站插件市场完整规划

> 日期：2026-08-31
>
> 状态：产品范围持续确认中；不是 MVP 规格，也不是技术栈或实施授权。
>
> 原则：已确认内容写为“决定”，设计推导写为“候选”，未确认问题保留选择，不擅自定案。

## 1. 市场在整个工作站中的位置

插件市场不是插件运行时，也不是时间轴本身。它解决的是发现、理解、获取、更新和管理；插件运行时负责页面、滤镜、工具、模型、Agent、Skill 和媒体处理能力真正接入工作站。

```text
在线市场：发现、推荐、分类、认证、统计、版本目录
                         ↓
本地插件管理器：下载、安装、启停、更新、回滚、卸载
                         ↓
插件运行时：注册页面、滤镜、时间轴工具、Agent、模型等扩展
                         ↓
项目与时间轴：插件实际创建和修改用户产物
```

决定：插件可以完整操作时间轴；市场中的警告和认证用于表达信任，不通过缩减未认证插件的功能来制造“安全版插件”。宿主不设置文件、网络、GPU、外部进程、时间线或 UI 的细粒度权限申请；manifest 中的贡献与运行要求是说明和装配信息，不是授权白名单。

## 2. 产品目标

1. 用户能找到适合自己创作任务的插件，而不要求理解底层技术类别。
2. 平台能明确展示自己的第一方插件，同时不压制未认证和社区插件的可见性。
3. 页面、滤镜、工具、Agent、Skill、模型、生成器、媒体处理器等不同形态都能被同一市场描述和管理。
4. 成功安装量、GitHub Stars、时间和认证状态含义清楚；不额外建设站内点赞，也不把 Stars 改名成点赞量。
5. 用户能看到当前安装了什么、贡献了什么、是否可更新、更新会改变什么，并能恢复失败更新。
6. 插件作者可以通过开放途径被收录；平台认证是额外承诺，不是进入市场的前提。

## 3. 已确认的信息架构

应用级入口：插件市场位于项目中心顶部一级标签，与“本地项目”和“工作流模板”并列；用户不需要先打开某个项目，也不需要进入设置页才能安装插件。“工作流模板”在此特指页面与插件的组合预设，不是自动化节点流程。

### 3.1 推荐

用途：方便平台展示第一方插件，并承载编辑精选和场景化发现。

必须具备：

- 第一方插件货架，明确标注“平台官方/第一方”。
- 可配置的推荐条目顺序、开始/结束时间和上下架状态。
- 点击进入同一套插件详情，避免推荐卡与普通市场条目形成两套事实。

候选货架：

- 平台官方插件。
- 编辑精选。
- 按创作场景：剧本与提示词、视频生成、剪辑增强、字幕与翻译、音频与 TTS、超分与导出。
- 新上架。
- 最近更新。
- 下载热门。
- 用户好评。

待确认：推荐页只做人工运营，还是同时加入基于本机工作流/已安装插件的个性化推荐。

### 3.2 插件市场 / 发现

必须具备：

- 全量浏览、搜索、分类、筛选和排序。
- 认证和未认证插件同场显示。
- 按成功安装量、GitHub Stars 和时间排序。
- 插件卡/条目保留用户指定的简洁骨架：左侧自定义图标，中间名称、GitHub 地址和介绍，右侧胶囊形下载按钮。
- 清楚显示第一方、认证、未认证、已安装、可更新、已弃用和不兼容等状态。

### 3.3 插件详情

完整信息候选：

- 名称、图标、作者、GitHub、网站、许可证、版本和更新日志。
- 长描述、截图、演示视频和使用说明。
- 插件贡献：页面、滤镜、工具、命令、Agent、Skill、模型、导入导出器等。
- 适用工作站版本、操作系统、CPU 架构、GPU/驱动、外部软件和模型依赖。
- 会访问的工程范围、网络、文件、外部进程和凭据类型；只做透明提示，不默认削减能力。
- 已知 UI 插槽冲突、快捷键冲突、扩展 ID 冲突、依赖冲突和加载顺序要求。
- 成功安装量、GitHub Stars、首次上架和最新稳定版发布时间，并标清来源。
- 认证报告、认证适用版本和最后复核时间。

### 3.4 已安装

必须具备：

- 当前版本、安装来源、认证状态、启用状态、是否正在被项目使用。
- 插件贡献清单及入口：页面、滤镜、工具、模型、Agent、Skill 等。
- 启用/停用、配置、打开来源、更新、卸载。
- 可更新筛选、更新数量徽标、单个更新和全部更新。
- 更新说明、兼容性变化、新增冲突和安装来源变化。
- 更新前恢复点、失败自动恢复，以及用户手动回退到上一版本。
- 缺失插件占位：项目引用的插件被卸载或不可用时，保留数据并提供重新安装或替代入口。

决定：更新管理放在“已安装”内部，不增加独立顶级更新页；更新数量徽标、可更新筛选、单个更新和全部更新均在这里完成。

## 4. 分类模型

单一类别无法同时回答“它是什么”和“它解决什么”。候选采用三个正交维度。

### 4.1 贡献形态 `contributionTypes`

- 页面 / 项目页面。
- 面板 / 检查器 / 工具栏。
- 时间轴工具 / 编辑命令。
- 剪辑/时间线实现；官方基础剪辑插件和替代实现都按插件版本、所实现的时间线契约版本、贡献与兼容信息登记。
- 有类型的数据端口、自定义数据类型与类型适配器；这些连接只传信息，不自带执行语义。
- 视频滤镜 / 音频滤镜 / 转场 / 生成器。
- Agent / LLM 工具 / Skill。
- 模型或模型连接器。
- 素材处理器 / 后台任务。
- 导入器 / 导出器 / 渲染器。
- 主题 / UI 组件。
- 自动化与项目模板。
- 游戏/交互内容引擎、运行预览与项目构建导出器，例如未来的 Galgame 引擎插件。

### 4.2 创作领域 `domains`

- 剧本与提示词。
- 图片/视频生成。
- 剪辑与时间轴。
- 字幕、ASR、OCR、纠正与翻译。
- TTS、配音、BGM 与音频修复。
- 画质增强、补帧、降噪、超分。
- 编码、压制与交付。
- 素材与项目管理。
- 开发者工具。

### 4.3 技术与环境标签 `tags`

模型/服务名、格式、硬件、操作系统、离线/联网、本地/云端、语言等可搜索标签。

决定：一个插件可以声明多个贡献形态和多个创作领域。最终分类名称、层级和图标需要单独确认。

## 5. 搜索、筛选与排序

### 5.1 搜索

候选权重：精确插件名/插件 ID > 前缀 > 作者 > 功能摘要 > 分类与标签 > 长描述。搜索结果仍可用当前选定指标作同相关度次排序。

### 5.2 筛选

- 贡献形态。
- 创作领域和标签。
- 第一方 / 认证 / 未认证。
- 已安装 / 未安装 / 可更新。
- 与当前工作站、操作系统和硬件兼容。
- 免费/付费、开源/闭源是否需要进入第一版数据模型仍待确认。

### 5.3 排序

已确认：

- 成功安装量。
- GitHub Stars。
- 时间。

候选明确为：

- 安装热门：近 30 天成功安装 / 全部成功安装。
- Stars 最多：GitHub 仓库 Stars 降序。
- 最新上架：`listedAt`。
- 最近更新：最新稳定版本的 `releasePublishedAt`。
- 最近活跃：`sourceUpdatedAt`，若用户确实需要源码活跃度。

待确认：默认排序是“综合/推荐”、下载量还是最近更新；升序是否需要暴露给普通用户。

## 6. 指标口径

### 6.1 成功安装量

候选事件链：

```text
download_requested
  → artifact_downloaded
  → install_started
  → install_succeeded / install_failed
```

决定：市场公开指标和排序使用“成功安装量”，不使用下载按钮点击、下载完成数、npm 下载量或 GitHub Release 下载量冒充安装量。只有本地插件管理器完成安装、宿主识别插件并提交安装事务后才产生 `install_succeeded`。

- 首次成功安装设备数与全部成功安装事件分别保存，便于后续选择展示口径。
- 重装事件可以记录，但不能与首次安装设备数混淆。
- `update_succeeded` 单独统计，不计入安装量。
- 离线时可以稍后补报；统计上报失败不能让已经成功的本地安装回滚。
- 绕过市场和本地插件管理器的手动安装不进入市场安装量。

### 6.2 GitHub Stars

决定：不建设站内点赞、点赞账号、点赞写入 API 或防刷系统。市场同步 GitHub 仓库 Stars，在卡片上使用星形图标显示，并支持按 Stars 排序。

边界：

- 文案明确写 `GitHub Stars` 或 `Stars`，不写“点赞量”。
- Stars 是仓库级外部信号；monorepo 中多个插件可能共享同一个 Stars 数字，详情页应说明来源仓库。
- 保存 `githubRepoId`、`stars` 和 `starsUpdatedAt`，避免仓库改名或统计过期后无法解释。
- GitHub 暂时不可用时显示最后同步值和刷新时间，不把缺失值显示为 0。

### 6.3 时间

- `listedAt`：首次进入公开目录，不随版本更新变化。
- `releasePublishedAt`：当前展示版本的发布时间。
- `sourceUpdatedAt`：代码仓库最近活动时间。
- `metricsUpdatedAt`：统计数据最后刷新时间。
- `certifiedAt` / `certificationExpiresAt`：认证有效期。

## 7. 推荐与认证

### 7.1 三个不能混淆的概念

| 概念 | 回答的问题 | 是否承诺质量 |
|---|---|---|
| 第一方 | 是不是平台自己制作/维护 | 由平台负责 |
| 认证 | 这个具体版本是否经过平台检查 | 是，范围以认证报告为准 |
| 推荐 | 是否占据推荐页运营位置 | 不自动等于认证或第一方 |

### 7.2 推荐后台候选能力

- 创建货架、命名、描述和封面。
- 选择插件、拖动排序、设定权重。
- 定时上架/下架和地区/语言范围。
- 预览推荐页。
- 记录操作人和变更历史。
- 自动货架可按下载、GitHub Stars、上架和更新数据生成，人工货架优先级规则待定。

### 7.3 认证记录候选字段

- 认证的插件 ID、版本和构建产物摘要。
- 工作站版本、操作系统和硬件测试范围。
- 检查项目、已知问题、最后复核时间和认证状态。
- 撤销原因与受影响版本。

## 8. 收录与作者流程

决定：插件公开收录流程直接参考 dsh-market：市场应用与公开 Registry 仓库分离，插件作者向 Registry 提交 PR；CI 校验条目并生成市场消费的 JSON 目录，市场客户端读取该目录。第一方插件同样进入统一目录，但可由平台维护者提交和审核。

“被收录”“被认证”“第一方”“被推荐”仍是不同状态；Registry PR 通过只代表进入目录，不自动获得认证或推荐。

## 9. 插件目录和版本数据候选

### 9.1 插件级

- 稳定 `pluginId` 与显示名称。
- 作者/组织、GitHub 和网站。
- 图标、短介绍、长介绍、截图与演示。
- `contributionTypes`、`domains`、`tags`。
- 第一方、认证、推荐和弃用状态。
- 许可证与商业模式。

### 9.2 版本级

- 版本号、发布日期、更新日志和更新通道。
- 下载来源、不可变摘要/校验值和仓库提交。
- 工作站 API 兼容范围、操作系统/架构、GPU 和外部依赖。
- 贡献清单、依赖、冲突和迁移说明。
- 认证记录必须绑定版本或明确的版本范围，不能自动无限继承。

## 10. 安装与更新流程

### 10.1 安装

```text
点击下载
  → 解析版本和来源
  → 展示贡献、兼容性、依赖与已发现冲突
  → 未认证插件追加醒目警告和免责声明
  → 用户确认
  → 下载并校验
  → 本地安装事务
  → 发现实际贡献并与 manifest 对比
  → 生效 / 提示刷新或重启 / 失败恢复
```

决定：未认证警告不阻止继续安装，也不削减插件能力。

### 10.2 更新

```text
检测最新兼容版本
  → 展示更新日志、来源和兼容变化
  → 若新增贡献/冲突则再次提醒
  → 创建本地恢复点
  → 下载并安装
  → 验证插件可加载
  → 成功提交 / 失败回到原版本
```

候选更新源：包管理器稳定版本、GitHub Release、固定提交、开发通道。正式市场默认跟随何种来源尚未决定。

## 11. 在线与本地系统边界

### 11.1 在线市场服务候选

- Catalog：插件、版本、分类、兼容性和来源。
- Search：搜索、筛选和排序索引。
- Editorial：推荐货架。
- Metrics：安装事件聚合、GitHub Stars 同步和展示统计。
- Identity：作者与组织身份；市场不因 Stars 展示而要求用户建立点赞账号。
- Certification：认证记录和撤销。
- Submission/Admin：收录、审核、运营和下架。

### 11.2 本地插件管理器候选

- 已安装清单和来源锁定。
- 安装、启停、更新、卸载和回滚。
- 依赖、扩展 ID、UI 插槽、快捷键和加载顺序冲突检查。
- 插件贡献发现与项目缺失插件占位。
- 用户同意后上报安装结果；离线时排队还是不统计待定。

## 12. 故障与恢复必须覆盖

- 下载中断、包损坏、来源消失。
- 插件版本与宿主不兼容。
- 依赖安装失败、构建脚本失败、GPU/模型依赖缺失。
- 插件加载后页面空白或宿主启动失败。
- 更新导致工程对象无法读取。
- 插件被下架、仓库转移、作者删除 Release。
- 未认证插件后来获得认证，或认证版本后来被撤销。
- 指标同步或推荐服务离线时，仍能浏览缓存目录和管理本机插件。
- 项目引用已卸载插件时保留数据，不因卸载而销毁项目产物。

## 13. 完整交付顺序候选

这是依赖顺序，不是 MVP 裁剪；所有已确认能力都留在完整目标中。

1. 固化已确认的成功安装量、最新稳定版发布时间和默认排序口径。
2. 定义插件/版本/贡献/认证/推荐/统计数据模型与公开 Registry 格式。
3. 定义本地插件管理器的安装、更新、回滚和状态契约。
4. 定义推荐、发现、详情、已安装和更新的完整交互规格。
5. 定义收录、作者验证、认证和推荐运营后台。
6. 定义安装统计、GitHub Stars 同步、搜索索引和离线降级。
7. 用官方基础剪辑插件、替代时间线实现、页面插件、有类型端口/适配器、视频滤镜、Agent/Skill、模型连接器、Galgame 引擎插件和导出器做协议覆盖验证。
8. 用户确认完整规格和架构路线后，才进入实施计划；当前不写产品代码。

## 14. 下一批待确认决策

1. 默认排序是综合/推荐、成功安装量、GitHub Stars 还是最近更新；是否向普通用户暴露升序。
2. 推荐页货架清单，以及第一方插件的默认位置和数量规则。
3. 安装产物优先级和稳定/测试/开发更新通道。
4. 评论、评分、主题专区、备份同步和诊断中心是否进入最终市场范围。
