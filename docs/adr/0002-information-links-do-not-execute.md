# ADR-0002：插件信息连接只传递上下文，不负责执行

## 状态

Accepted — 用户于 2026-09-01 明确确认。

## 背景

工作站同时存在三种容易混淆的关系：

1. 项目页面装配：决定项目显示哪些页面及其顺序。
2. 插件信息连接：让页面或插件获得其他插件、项目和时间线的信息。
3. 自动化：连续调用多个能力、等待任务、处理失败并继续推进流程。

用户希望插件可以像节点一样手动拉线，也可以自动匹配兼容信息。例如将时间线连接给字幕页后，字幕页立即获得当前时间线和素材上下文，成为可用页面。同时，工作站已经决定通过 MCP 向第三方 Agent 暴露能力，由 Agent 负责完整自动化。

如果普通信息连线也自动执行，用户只想让字幕页看见时间线时就可能意外启动 ASR、OCR、翻译或写入工程，也会与 Agent/MCP 自动化形成两套执行语义。

## 决定

插件信息连接只建立数据和上下文绑定，不触发接收插件执行。

```text
页面装配图：决定“看见哪些页面”

信息连接图：决定“插件能取得哪些信息”
时间线 ──信息──> 字幕页

Agent / MCP：决定“何时调用什么能力”
读取时间线 → 调用 ASR → 等待 → 调用翻译 → 写入字幕
```

具体规则：

1. 手动拉线和“自动连接”都只建立兼容端口之间的信息绑定；自动连接是自动配线，不是自动执行。
2. 接收插件可以读取连接提供的当前项目、时间线、素材、选区、播放头、字幕轨、任务结果或其他声明类型。
3. 插件操作由用户在页面中主动触发，或者由 Agent 通过 MCP 显式调用公开能力。
4. 上游信息变化可以更新接收插件的上下文显示，但不得隐式启动生成、分析、媒体处理或工程写入。
5. Agent/MCP 负责多步骤顺序、任务等待、重试、失败决策和结果提交；自动化行为进入统一任务、事务、版本和归档体系。
6. 页面装配图、信息连接图和 Agent 自动化记录分别保存，不能把一类连线加载成另一类行为。

## 后果

### 正面

- 用户可以放心连接时间线和插件页面，不会因为查看或选择变化意外启动昂贵任务。
- 信息互操作与自动化编排职责清晰，插件作者只需声明自己需要什么信息以及提供什么能力。
- Agent 可以读取同一信息连接形成的上下文，并通过 MCP 统一执行完整流程。
- 避免再造一套与 MCP 重叠的节点执行器。

### 负面

- 单靠拉线不能得到 ComfyUI 式“一键运行整图”，必须由用户操作或配置 Agent。
- Agent/MCP 层需要具备明确的能力发现、任务订阅、失败恢复和结果提交协议。
- 持续上下文绑定仍需处理频繁更新、过期引用和大型媒体传输效率。

### 中性

- 插件可以在 UI 中根据上下文即时更新预览和可用状态，只要这种更新不等同于启动处理任务或写入工程。
- 未来自动化插件可以用可视化节点表示 Agent/MCP 调用，但那是独立的执行图，不复用信息连线的语义。

## 失败模式与控制方向

| 失败模式 | 控制方向 |
|---|---|
| 自动连接选错同类型端口 | 显示匹配依据，允许预览、撤销和重新选择 |
| 时间线选区变化导致插件拿到过期对象 | 引用带对象版本和有效性状态，执行前由用户或 Agent 再确认 |
| 上下文更新形成 UI/事件循环 | 标记更新来源、合并高频事件并检测循环 |
| 插件缺失后连接消失 | 保存连接占位和类型信息，重装兼容插件后恢复 |
| 大视频通过连接被反复复制 | 传递素材/范围句柄与访问视图，不默认复制完整媒体 |
| 插件在收到上下文时自行偷偷执行 | 规范区分 context-update 与 capability-call；认证测试检查明显违规行为，未认证插件仍按既定开放策略提示用户 |

## 考虑过的替代方案

### 信息连线同时作为执行连线

优点是接近 ComfyUI，可直接运行整条图。拒绝作为普通连接语义，因为它会让页面联动产生意外执行，并与 Agent/MCP 自动化重复。

### 同一条线提供“数据模式/执行模式”开关

表面上灵活，但同一图在不同模式下含义改变，项目共享、调试和故障恢复更难。若未来需要可视化自动化，应建立独立 Agent/MCP 执行图。

## 尚未决定

- 首批公共信息类型及字段。
- 信息连接是快照、实时引用还是可选择两者。
- 自动连接的匹配优先级与确认交互。
- Agent 如何读取项目已有连接并转换为 MCP 调用上下文。
- 大媒体句柄、跨进程共享和远程插件的数据访问方式。
