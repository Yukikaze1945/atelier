# ADR-0001：Core 定义时间线契约，插件提供剪辑实现

## 状态

Accepted — 用户于 2026-09-01 选择方案 C。

## 背景

AI 创作工作站需要同时满足：

- 安装后自带可用的基础剪辑能力。
- 剪辑页可以按项目选择、替换或不启用，而不是不可替换的 Core 页面。
- 视频生成、字幕、TTS、超分、Galgame 等不同插件和项目类型都能与时间线交换输入并取回结果。
- 插件缺失、升级或替换后，项目中的时间线数据、片段和处理结果仍可保存、识别和恢复。
- 时间线修改继续进入统一事务、Undo/Redo、版本、事件和归档体系。
- 插件可以扩展专有能力，但不能迫使其他插件直接依赖它的内部类或私有文件格式。

还需要兼顾长期工程兼容、跨插件互操作、实现替换自由、实时预览性能和开放插件生态。当前不选择具体 UI 框架、媒体引擎、序列化格式或 GPU 交换技术。

## 决定

采用“稳定契约 + 可替换实现”边界：

```text
项目 / 产物 / 事务 / 版本 / 归档
                 │
        Core 时间线契约与能力发现
                 │
       ┌─────────┴─────────┐
       │                   │
官方基础剪辑插件      其他兼容时间线插件
引擎 / 页面 / 播放     引擎 / 页面 / 播放
       └─────────┬─────────┘
                 │
       有类型的插件信息连接图
   生成 / 字幕 / TTS / Galgame / Agent
```

Core 负责：

1. 定义版本化、可迁移的时间线公共契约，以及对象 ID、媒体引用、时间基准、版本和来源等共同语义。
2. 定义通用时间线事务、验证、事件、Undo/Redo 和归档要求。
3. 发现当前可用的时间线实现，并在实现缺失时保留数据和连接占位。
4. 允许命名空间扩展数据随项目保存，同时标明它依赖哪个实现、版本和降级条件。

插件负责：

1. 实际时间线引擎、剪辑页面、交互工具、播放预览和媒体处理。
2. 声明自己实现的契约版本、可选能力、专有扩展和资源要求。
3. 通过公共契约与有类型端口接收其他插件的素材、选区和任务结果，并把处理结果返回项目或调用方。

默认安装包预装官方基础剪辑插件，但 Core 和其他插件不得通过硬编码插件 ID 才能访问时间线；调用方按时间线能力与契约版本发现实现。

## 后果

### 正面

- 保持开箱即用，同时允许替换剪辑体验和引擎。
- 非视频项目也能把时间线作为可选视频处理能力，而不必采用线性时间线作为唯一项目结构。
- 项目数据不因页面或实现插件卸载而丢失。
- 插件可以围绕稳定类型交换素材、范围和结果，减少两两适配和直接依赖。
- 为未来多个剪辑实现、Galgame 引擎和第三方 Agent 留出空间。

### 负面

- Core 时间线契约会成为高成本兼容面，需要版本治理、迁移和一致性测试。
- 契约过小会导致插件互操作不足；过大则会把某一剪辑实现重新固化进 Core。
- 插件专有功能切换到另一实现时可能只能保留，无法完整编辑或预览。
- 项目控制契约与实时帧/音频高速数据路径必须分层，否则跨边界复制会损害预览性能。

### 中性

- 官方基础剪辑插件仍然是默认体验，但其“第一方”身份不等于 Core 特权。
- 项目可能需要记录所选时间线实现及其版本，同时保存契约层数据和实现扩展数据。
- 兼容实现是否可以同时激活、如何切换以及切换时怎样预览差异，后续另行决定。

## 失败模式与控制方向

| 失败模式 | 控制方向 |
|---|---|
| 契约变成最低公分母，复杂剪辑能力无法交换 | 公共核心 + 命名空间扩展 + 明确能力声明 |
| 插件卸载后项目打不开 | Core 保留契约层数据、连接和缺失实现占位 |
| 替换实现后专有功能静默丢失 | 切换前兼容报告；扩展数据只保留不删除；允许取消和回退 |
| 不同实现对同一操作含义不一致 | 契约一致性测试、规范示例工程和行为级测试套件 |
| 实时预览因跨插件数据复制变慢 | 项目控制契约与媒体高速路径分离；GPU surface/共享内存另立决策 |
| 其他插件直接依赖官方剪辑插件 | 按能力和契约版本发现实现，禁止把官方插件 ID 写成互操作前提 |

## 考虑过的替代方案

### A：只插件化剪辑 UI

Core 持有完整时间线模型、引擎、播放和渲染，插件只替换界面。互操作最简单，但编辑引擎不可真正替换，不符合用户要求的插件自由度。

### B：整套时间线完全属于插件

Core 只保留通用项目与插件连接。自由度最高，但各时间线实现容易形成私有项目格式，其他插件难以稳定交换选区和结果，插件缺失后的工程恢复也最困难。

### C：Core 定义契约，插件提供实现

在自由度和互操作之间取得平衡。用户已选择本方案。

## 尚未决定

- 时间线公共契约的最小对象与字段。
- 契约序列化、交换和迁移格式。
- 实现兼容等级和一致性测试套件。
- 专有扩展在切换实现时的降级 UX。
- 播放、渲染、缓存、GPU surface 和共享内存等高速路径。
- 多个时间线实现的选择、并存和切换规则。
