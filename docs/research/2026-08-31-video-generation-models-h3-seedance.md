# 视频生成模型第一轮调研：MiniMax H3 本地与 Seedance 2.0 / 2.5 云端

> 调研日期：2026-08-31  
> 状态：研究记录，不代表最终连接器优先级或技术栈决定。  
> 范围：只比较与 AI 创作工作站接入有关的部署、能力、时间轴语义和风险；不编写实现代码。

## 1. 结论先行

1. MiniMax H3、Seedance 2.0 和 Seedance 2.5 可以共用一个“视频生成”宿主能力，但不能共用一套写死的参数表。
2. MiniMax H3 提供真正可用的本地 H3-Base 路线；官方开放权重生成 768p 音视频，完整官方 2K 工作流仍是“本地 H3-Base + 云端 Context-IR/Regenerate-2K”的混合流程。
3. 当前工作站的 RTX 5060 Ti 16GB 已经能通过 ComfyUI 的 INT8、显存交换/内存卸载和 Turbo LoRA 跑 H3。它是经过本机输出验证的消费级优化路线，不是官方 BF16 四卡参考部署。
4. Seedance 2.5 已于 2026-08-06 在 BytePlus ModelArk 正式开放 API，不再只是产品预览。
5. Seedance 2.5 不是 Seedance 2.0 的简单完全替代：2.5 强在 30 秒叙事、大量参考素材和精细编辑；2.0 当前仍有更高输出分辨率及 Fast/Mini 成本档。
6. 工作站应按运行时能力表显示可用选项，项目文件保存抽象请求、实际模型版本和原始 Provider 参数，不能把某个品牌字段固化进 Core。

## 2. MiniMax H3：官方模型与本地部署

### 2.1 官方开放了什么

MiniMax 把完整 H3 系统拆成三层：

| 层 | 作用 | 是否开放本地权重 |
|---|---|---|
| H3-Context-IR | 理解并整理自由形式的文本、图片、视频和音频参考，产生结构化上下文 | 否；官方提供 API 与提示词指南 |
| H3-Base | 联合预测视频与立体声音频，输出 768p | 是 |
| H3-Regenerate-2K | 根据上下文与低分辨率结果重新生成 2K 版本 | 尚未开放；官方提供 API |

H3-Base 有两个任务家族：

- FL2VA：文本生成音视频，以及首帧/尾帧/首尾帧生成音视频。
- Ref2VA：使用文本和任意组合的参考图片、视频、音频生成音视频。

官方 H3-Base 是 33B 稠密 Omni Transformer，文本编码器使用完整 Qwen3-VL-32B 权重；视频和音频由不同 VAE 表示，最终联合生成视频与 32kHz 立体声音频。官方权重是 BF16，并给出的 SGLang 参考命令使用 4 张 GPU。

因此需要明确三种口径：

- “H3 完全本地”目前准确指开放的 H3-Base 768p 生成。
- “H3 官方 2K 效果”目前需要云端服务参与，不是完全离线。
- “单张消费级显卡跑 H3”依赖社区/ComfyUI 量化和卸载，不是官方原始 BF16 参考配置。

### 2.2 本机已经存在并验证的消费级路线

当前机器：NVIDIA GeForce RTX 5060 Ti，16311 MiB 显存。

当前 API 工作流使用 Ref2VA 路线，主要文件为：

| 组件 | 当前文件口径 | 磁盘体积 |
|---|---|---:|
| Ref2VA DiT | pruned INT8 ConvRot | 19.53 GiB |
| Qwen3-VL 文本编码器 | INT8 ConvRot | 25.28 GiB |
| Video VAE | INT8 ConvRot | 2.95 GiB |
| Audio VAE | FP32 | 0.56 GiB |
| Turbo LoRA | 4-step 系列 | 0.58 GiB |
| **当前 Ref2VA 活跃路线合计** | 不含 ComfyUI、缓存、输入输出 | **约 48.90 GiB** |

若同时保留 FL2VA INT8 DiT，再增加 19.53 GiB；两种任务家族与共用组件合计约 68.43 GiB。此前“约 69GB”是完整双路线模型集，不是单一路线最低安装量。

当前工作流的工程措施包括：

- 0.4MP 分辨率档、24fps。
- 约 5–15 秒的帧长范围；当前默认 124 帧约为 5.17 秒。
- 模型分块交换、预留显存控制、内存高效注意力与缓存。
- Turbo LoRA 降低采样步数。
- Ref2VA 节点可以同时接收参考图片、视频、视频音频和独立音频；没有参考素材时也可走纯文本生成。

本机现有输出中已检查到一个 10.125 秒、576×736、24fps、H.264 + 32kHz 双声道 AAC 的合成结果。因此“16GB 本地 H3 能产出带同步音频的视频”已有本机事实支撑，但还不能据此承诺所有分辨率、时长和参考组合都稳定。

### 2.3 对工作站接入的意义

第一版本地 H3 连接器可以把 ComfyUI 当执行后端，因为现有环境、工作流和结果已经存在。宿主不应把 ComfyUI 节点名写进项目领域对象，而应保存：

- 抽象生成请求。
- 连接器 ID、连接器版本、实际工作流版本和模型文件指纹。
- 生成输出与同步音频。
- 实际使用的低层参数快照，以便重现或诊断。

未来可以增加 SGLang、vLLM-Omni 或 Diffusers 连接器；它们是同一个模型能力的其他执行实现，不需要改变项目时间轴格式。

### 2.4 许可不是普通开源许可证

MiniMax H3 使用 MiniMax H3 Community License。当前官方条款至少包含：

- 商业产品或服务的界面需要显著展示“MiniMax H3”。
- 年收入超过 2000 万美元的商业产品/服务需要另行书面授权。
- 分发权重时需要附带协议与 NOTICE，并受适用地区限制。
- 对向第三方提供生成能力的产品，条款要求维持相应使用限制与保障措施。

因此插件市场不能只把它标成“开源模型”后结束。连接器清单需要声明许可证、地域、归属展示和是否分发权重；最终商业发布前仍需针对目标地区复核法律文本。

## 3. Seedance 2.0 云端

### 3.1 当前正式能力

BytePlus 当前主要模型 ID：`dreamina-seedance-2-0-260128`，另有 Fast 与 Mini 档。

API 支持：

- 文生视频。
- 首帧、首尾帧生成。
- 图片、视频、音频及其组合参考。
- 对已有视频进行编辑与续写。
- 生成同步音频。
- 异步任务、回调、查询、取消/删除，以及返回尾帧供连续生成。

当前增强生成 API 的输出口径为 24fps、4–15 秒。2.0 主模型支持 480p、720p、1080p；BytePlus LAS 增强算子还列出 4K 输出，并明确其管线集成了视频超分等前后处理。因此计划里应把“模型生成分辨率”和“增强管线最终输出分辨率”分开记录，不能把增强后的 4K 统一描述成模型原生 4K。

多模态参考的当前主要限制：

- 1–9 张参考图片。
- 最多 3 段参考视频，总时长不超过 15 秒。
- 最多 3 段参考音频，总时长不超过 15 秒。
- 音频不能单独作为唯一参考，至少还要有图片或视频。

### 3.2 为什么 2.0 仍值得保留

- 4–15 秒非常适合时间轴上的短镜头替换和插入。
- 主模型当前提供比 2.5 更高的输出分辨率档。
- Fast/Mini 可以作为预览、批量尝试和成本优先档。
- 连接器可以在同一个页面里提供“质量优先 / 速度优先 / 成本优先”能力实现，不要求用户理解底层端点名。

## 4. Seedance 2.5 云端

### 4.1 当前正式状态

Seedance 2.5 于 2026-07-31 正式发布，2026-08-06 已在 BytePlus ModelArk 的受支持市场提供 API。当前模型 ID 为 `dreamina-seedance-2-5-260628`。

当前官方能力：

- 单次生成 4–30 秒、24fps、带同步音频的视频。
- 最多 30 张图片、10 段视频和 10 段音频，共 50 份多模态参考。
- 音频可以作为唯一参考。
- 支持首帧、首尾帧、参考生成、视频编辑与续写。
- 支持在提示词中按时间段控制叙事、机位、动作和节奏，并对已有视频中的特定时间片段做定向修改。
- 官方产品页说明可继续延长两次，以形成更长叙事。

当前 BytePlus API 输出分辨率只有 480p 和 720p。2.5 的核心优势不是分辨率，而是长片段叙事、参考容量、连续性和精细编辑。

### 4.2 与时间轴产品的直接契合点

2.5 的时间戳级提示词非常接近我们的“提示词区域对应时间段”设想，但应注意：

- 模型内部时间控制只是生成条件，不等于宿主时间轴。
- 宿主仍应把提示词段保存成自己的时间对象，再由插件编译成 2.5 的时间戳提示词。
- 生成后局部修改应产生新版本，并保留原片段和修改范围，不应直接覆盖唯一文件。
- 30 秒模型片段可以覆盖多个镜头；是否拆成一个时间轴片段、多个镜头片段或嵌套片段，应由页面/插件给用户选择。

### 4.3 云端约束

- API 返回异步任务 ID；任务记录只保留 7 天，成功结果是预签名地址。连接器必须把结果及时下载并导入工程，不能把远端 URL 当永久素材。
- 真实人脸参考素材受服务方限制，通常需要经过授权素材库。它不是宿主可用免责声明绕过的本地限制，插件必须能展示 Provider 拒绝原因和素材入库要求。
- 价格随输入是否含视频、输入/输出时长和分辨率变化。宿主应提供生成前估算和生成后实际用量记录，但价格表应由插件在线更新，不能固化在项目格式里。
- BytePlus 当前有地区可用性限制；连接器需要在账号配置时探测可用区域。

## 5. 三者对比

| 维度 | MiniMax H3 本地优化路线 | Seedance 2.0 云 API | Seedance 2.5 云 API |
|---|---|---|---|
| 主要价值 | 离线、本地数据、无按次费用、可改工作流 | 短片段、较高分辨率、Fast/Mini 成本档 | 30 秒叙事、大量参考、时间戳级控制与编辑 |
| 输入 | 文本；首尾帧；图片/视频/音频参考，取决于 FL2VA/Ref2VA | 文本、图片、视频、音频及组合 | 文本、最多 30 图 + 10 视频 + 10 音频 |
| 输出音频 | 原生立体声音频 | 原生同步音频 | 原生同步音频 |
| 当前时长 | 本机工作流约 5–15 秒 | 4–15 秒 | 4–30 秒 |
| 当前分辨率 | 官方 H3-Base 768p；本机当前为 0.4MP 档 | 主模型至 1080p；增强算子可给 4K 管线结果 | 480p / 720p |
| 资源/费用 | 占用本地 GPU、RAM、磁盘和时间；当前 Ref 路线约 48.90 GiB 权重 | 按云端用量付费 | 按云端用量付费，长片段和大量参考需重点显示预估 |
| 数据位置 | 本地 | 上传云端 | 上传云端 |
| 结果保存 | 直接进入本地任务输出 | 必须在链接过期前下载 | 必须在链接过期前下载 |
| 主要风险 | 量化兼容、速度、显存/内存压力、工作流漂移、社区许可证 | 成本、网络、审核、区域、API 版本 | 同左，并且当前分辨率低于 2.0 主模型 |

## 6. 建议的宿主能力契约候选

这一部分是研究建议，尚未成为最终 API 决定。

### 6.1 能力发现

连接器在运行时报告：

- 支持的模式：T2V、首帧、首尾帧、参考生成、视频编辑、续写。
- 输入素材类型、数量、格式、时长和尺寸限制。
- 可用时长、宽高比、分辨率、帧率和音频开关。
- 是否支持 seed、尾帧返回、时间戳提示词、局部编辑、进度、取消和回调。
- 本地资源估算或云端费用估算。

页面根据能力表生成选项。这样 2.5 的 30 秒、2.0 的 1080p/HQ 和 H3 的本地档不会互相伪装成同一组能力。

### 6.2 通用请求

通用部分至少应表达：

- 提示词及可选的宿主时间段提示词对象。
- 参考素材列表，每项具有角色、顺序和可选源时间范围。
- 目标时长、宽高比、分辨率偏好和是否生成音频。
- 调用上下文：素材库生成，或时间轴上的目标轨道、插入点/选区、替换策略。
- 结果策略：只加入素材库、插入时间轴、替换选区或作为候选版本附着。
- Provider 扩展参数快照；Core 不解释但要保存。

### 6.3 统一结果与版本关系

无论本地还是云端，都归一为：

- 一个视频素材，以及可选的内嵌/独立音频表示。
- 精确时长、帧率、分辨率、声道和编码信息。
- 来源连接器、模型 ID、模型版本、请求参数、参考素材关系和生成时间。
- 对应的提示词段与宿主时间范围。
- 父版本、编辑范围、续写来源和尾帧引用。
- 失败、取消、审核拒绝、资源不足等结构化任务结果。

生成失败不得留下半个时间轴修改；成功后把“素材入库 + 可选时间轴放置”作为一个工程事务提交。旧结果进入版本链或归档，可恢复，不立即物理删除。

## 7. 当前建议与待用户决定

候选接入组合：

- MiniMax H3 本地连接器：作为离线、本地可控的基准实现。
- Seedance 2.0 连接器：作为短镜头、高分辨率和成本分档实现。
- Seedance 2.5 连接器：作为长镜头、多参考和精细编辑实现。

这三者形成互补，而不是“选择一个后删掉其他两个”。仍需用户决定：

1. 第一批正式连接器是否三者都纳入，还是先定一个本地 + 一个云端。
2. 云端首发接中国大陆火山方舟、国际 BytePlus，还是由同一插件提供两个地区配置。
3. 视频生成页生成成功后的默认行为：只入素材库、自动插入目标时间范围，还是每次询问。
4. 生成视频包含原生音频时，默认作为视频内嵌音频、自动拆出链接音轨，还是提供项目级偏好。
